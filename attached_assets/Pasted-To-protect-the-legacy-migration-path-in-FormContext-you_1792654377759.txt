To protect the legacy migration path in `FormContext`, you need a regression test that explicitly seeds storage with **unversioned data** (the old format) and verifies it gets migrated correctly on load. You should also add a contrasting test proving that **already-versioned data is not re-migrated** (the guard working as intended).

Here's a focused regression suite:

---

## 1. Understand the Two Formats

```typescript
// ❌ LEGACY (pre-versioning) — no `version` field
const legacyFormData = {
  name: "Budi",
  email: "budi@example.com",
  grade: "B",
  // no `version` key at all
};

// ✅ CURRENT (versioned) — has `version` field
const versionedFormData = {
  version: 2,
  name: "Budi",
  email: "budi@example.com",
  grade: "B",
};
```

The migration guard should:
- **Migrate** legacy data (no `version`) → upgrade to current version, add missing fields
- **Skip** versioned data (has `version`) → leave it untouched

## 2. The Regression Test Suite

```javascript
import { render, waitFor } from '@testing-library/react';
import { FormProvider, useFormData } from './FormContext';
import { CURRENT_FORM_VERSION } from './formConstants';

// Helper to seed storage with raw JSON
const seedStorage = (key, data) => {
  localStorage.setItem(key, JSON.stringify(data));
};

const STORAGE_KEY = 'form_data';

describe('FormContext — Legacy Data Migration (Regression)', () => {
  beforeEach(() => {
    localStorage.clear();
  });

  // ─────────────────────────────────────────────────────────────
  // REGRESSION: Legacy unversioned data must be migrated on load
  // ─────────────────────────────────────────────────────────────
  it('migrates legacy unversioned storage entries to the current version', async () => {
    // Arrange: seed storage with OLD format (no version field)
    const legacyData = {
      name: 'Siti',
      email: 'siti@example.com',
      grade: 'C',
      // intentionally no `version` key
    };
    seedStorage(STORAGE_KEY, legacyData);

    let capturedData = null;
    const Consumer = () => {
      const data = useFormData();
      capturedData = data;
      return null;
    };

    // Act: mount the provider — it should detect legacy data and migrate
    render(
      <FormProvider>
        <Consumer />
      </FormProvider>
    );

    // Assert: the data is now versioned and contains migrated fields
    await waitFor(() => {
      expect(capturedData).not.toBeNull();
      expect(capturedData.version).toBe(CURRENT_FORM_VERSION);
      expect(capturedData.name).toBe('Siti');
      expect(capturedData.email).toBe('siti@example.com');
      expect(capturedData.grade).toBe('C');
    });

    // Assert: storage itself was updated to the versioned format
    const stored = JSON.parse(localStorage.getItem(STORAGE_KEY));
    expect(stored.version).toBe(CURRENT_FORM_VERSION);
  });

  // ─────────────────────────────────────────────────────────────
  // GUARD: Already-versioned data must NOT be re-migrated
  // ─────────────────────────────────────────────────────────────
  it('does NOT re-migrate data that already has a version field', async () => {
    // Arrange: seed storage with CURRENT versioned format
    const versionedData = {
      version: CURRENT_FORM_VERSION,
      name: 'Andi',
      email: 'andi@example.com',
      grade: 'A',
    };
    seedStorage(STORAGE_KEY, versionedData);

    let capturedData = null;
    const Consumer = () => {
      capturedData = useFormData();
      return null;
    };

    render(
      <FormProvider>
        <Consumer />
      </FormProvider>
    );

    await waitFor(() => expect(capturedData).not.toBeNull());

    // Assert: data is unchanged — migration guard skipped it
    expect(capturedData.version).toBe(CURRENT_FORM_VERSION);
    expect(capturedData.name).toBe('Andi');

    // Assert: storage bytes are identical (no unnecessary write)
    const stored = JSON.parse(localStorage.getItem(STORAGE_KEY));
    expect(stored).toEqual(versionedData);
  });

  // ─────────────────────────────────────────────────────────────
  // EDGE CASE: Legacy data with missing fields gets defaults
  // ─────────────────────────────────────────────────────────────
  it('fills in missing fields with defaults when migrating legacy data', async () => {
    // Arrange: very old data missing fields added in later versions
    const ancientData = {
      name: 'Dewi',
      // no email, no grade — fields added in v2
    };
    seedStorage(STORAGE_KEY, ancientData);

    let capturedData = null;
    const Consumer = () => {
      capturedData = useFormData();
      return null;
    };

    render(
      <FormProvider>
        <Consumer />
      </FormProvider>
    );

    await waitFor(() => expect(capturedData).not.toBeNull());

    // Assert: legacy fields preserved, new fields defaulted
    expect(capturedData.version).toBe(CURRENT_FORM_VERSION);
    expect(capturedData.name).toBe('Dewi');
    expect(capturedData.email).toBe('');         // default value
    expect(capturedData.grade).toBe('A');        // default value
  });
});
```

## 3. Why This Protects the Compatibility Path

| Risk | How the test catches it |
|---|---|
| Developer removes legacy migration code ("it's been years, nobody has old data") | First test fails immediately — legacy data no longer migrates |
| Migration guard is loosened and re-processes versioned data | Second test fails — storage bytes change unexpectedly |
| New required field added but no default for legacy migration | Third test fails — missing field is `undefined` instead of defaulted |
| Version constant bumped but migration logic not updated | First test fails — `version` doesn't match `CURRENT_FORM_VERSION` |

## 4. Implementation Checklist for `FormContext`

Make sure your context code follows this shape so the tests pass:

```javascript
// FormContext.js
export const CURRENT_FORM_VERSION = 2;

const DEFAULTS = {
  name: '',
  email: '',
  grade: 'A',
};

function migrateIfNeeded(raw) {
  if (!raw) return { ...DEFAULTS, version: CURRENT_FORM_VERSION };

  // LEGACY PATH: no version field → migrate
  if (raw.version === undefined) {
    return {
      ...DEFAULTS,
      ...raw,
      version: CURRENT_FORM_VERSION,
    };
  }

  // GUARD: already versioned → return as-is
  return raw;
}

export function FormProvider({ children }) {
  const [data, setData] = useState(() => {
    const stored = localStorage.getItem(STORAGE_KEY);
    const parsed = stored ? JSON.parse(stored) : null;
    return migrateIfNeeded(parsed);
  });

  useEffect(() => {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(data));
  }, [data]);

  // ...
}
```

## 5. Key Takeaway

The regression test's job is to **freeze the contract** between old storage format and the current context. Without it, any cleanup PR that "simplifies" the migration logic will silently break users with pre-versioning data. The three tests together lock down:

1. **Legacy → Current** migration works
2. **Current → Current** is a no-op (the guard)
3. **Missing fields** get safe defaults during migration

Add this suite alongside your existing versioned-record tests, and the compatibility path stays protected as the form schema continues to evolve.
