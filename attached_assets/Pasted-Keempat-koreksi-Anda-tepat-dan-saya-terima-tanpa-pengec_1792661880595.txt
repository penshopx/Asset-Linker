## 2. Array Kosong ≠ Semua Email Berhasil

Koreksi ini penting dan saya lewatkan. `failedBuyerEmails.length === 0` memiliki tiga makna berbeda yang tidak boleh disamakan:

| Keadaan | Arti sebenarnya | Tindakan yang aman |
|---|---|---|
| Data berhasil dimuat, array kosong | Tidak ada email gagal pada rentang data ini | Reset filter boleh dipertimbangkan |
| Pemuatan awal (data belum ada) | Belum diketahui | Jangan reset, jangan tampilkan pesan |
| Refresh gagal / data belum lengkap | Status tidak diketahui | Jangan reset, jangan tampilkan pesan |

Reset otomatis hanya aman setelah **pengambilan data berhasil** dan **cakupannya memang cukup** untuk memastikan tidak ada email gagal. Tanpa dua syarat ini, reset bisa menyembunyikan filter yang masih relevan.

## 3. URL Filter Bukan Solusi, Hanya Pelengkap

Saya keliru menyebut Solusi 3 sebagai "paling robust". Faktanya:

- URL filter **mempertahankan** filter setelah refresh — ini justru memperparah masalah yang Anda deskripsikan (filter aktif, tombol keluar hilang).
- URL filter berguna untuk **bookmark dan berbagi**, bukan untuk menjamin kontrol selalu tersedia.
- Tetap butuh tombol keluar yang selalu muncul saat filter aktif, terlepas dari apakah filter disimpan di state lokal atau URL.

Jadi URL filter adalah **pelengkap** untuk kasus penggunaan tertentu, bukan pengganti Solusi 1.

## 4. Pesan yang Tepat

Pesan "Semua email berhasil dikirim" memang terlalu kuat jika hanya didasarkan pada array kosong. Pesan yang tepat adalah:

> **"Tidak ada pesanan dengan email gagal"** — dan hanya ditampilkan **setelah data berhasil dimuat**.

Pembedaannya:
- "Semua email berhasil" → klaim tentang proses pengiriman (butuh bukti dari backend/email service)
- "Tidak ada pesanan dengan email gagal" → pernyataan tentang data yang sedang ditampilkan (bisa diverifikasi dari array yang dimuat)
