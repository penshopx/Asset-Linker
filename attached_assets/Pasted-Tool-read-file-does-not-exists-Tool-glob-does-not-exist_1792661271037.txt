## Solusi 1: Pisahkan Kontrol Filter dari Banner (Recommended)

Tombol keluar filter harus selalu tersedia saat filter aktif, terlepas dari status email:

```typescript
// AdminPesanan.tsx
const [filter, setFilter] = useState<'all' | 'failed'>('all');
const [failedBuyerEmails, setFailedBuyerEmails] = useState<string[]>([]);

// Banner notifikasi (tetap hanya muncul saat ada email gagal)
{failedBuyerEmails.length > 0 && (
  <div className="banner notification">
    <span>{failedBuyerEmails.length} email gagal dikirim</span>
    <button onClick={() => retryFailedEmails()}>
      Retry
    </button>
  </div>
)}

// Kontrol filter (selalu tersedia saat filter aktif)
{filter === 'failed' && (
  <div className="filter-controls">
    <span>Menampilkan: Pesanan dengan email gagal</span>
    <button 
      onClick={() => setFilter('all')}
      className="btn-secondary"
    >
      Tampilkan semua pesanan
    </button>
  </div>
)}

// Tombol untuk mengaktifkan filter (hanya muncul jika ada email gagal)
{failedBuyerEmails.length > 0 && filter === 'all' && (
  <button 
    onClick={() => setFilter('failed')}
    className="btn-primary"
  >
    Tampilkan pesanan gagal saja
  </button>
)}
```

## Solusi 2: Reset Filter Otomatis Ketika Tidak Ada Email Gagal

Jika Anda ingin filter otomatis nonaktif ketika tidak ada lagi email gagal:

```typescript
// AdminPesanan.tsx
useEffect(() => {
  // Reset filter ketika semua email gagal sudah berhasil
  if (failedBuyerEmails.length === 0 && filter === 'failed') {
    setFilter('all');
  }
}, [failedBuyerEmails, filter]);

// Banner dengan kontrol filter terintegrasi
{failedBuyerEmails.length > 0 && (
  <div className="banner">
    <span>{failedBuyerEmails.length} email gagal dikirim</span>
    <div className="banner-actions">
      <button onClick={() => retryFailedEmails()}>
        Retry
      </button>
      {filter === 'all' && (
        <button onClick={() => setFilter('failed')}>
          Tampilkan pesanan gagal
        </button>
      )}
      {filter === 'failed' && (
        <button onClick={() => setFilter('all')}>
          Tampilkan semua pesanan
        </button>
      )}
    </div>
  </div>
)}

// Fallback: jika filter masih 'failed' tapi tidak ada email gagal
{filter === 'failed' && failedBuyerEmails.length === 0 && (
  <div className="info-banner">
    <span>Semua email berhasil dikirim</span>
    <button onClick={() => setFilter('all')}>
      Tampilkan semua pesanan
    </button>
  </div>
)}
```

## Solusi 3: Filter Berbasis URL (Paling Robust)

Jika filter disimpan di URL, masalah "Refresh tidak membantu" juga teratasi:

```typescript
// Menggunakan URL params
const [searchParams, setSearchParams] = useSearchParams();
const filter = searchParams.get('filter') || 'all';

const setFilter = (newFilter: string) => {
  if (newFilter === 'all') {
    searchParams.delete('filter');
  } else {
    searchParams.set('filter', newFilter);
  }
  setSearchParams(searchParams);
};

// Kontrol filter selalu tersedia
{filter === 'failed' && (
  <div className="filter-bar">
    <span>Filter: Pesanan dengan email gagal</span>
    <button onClick={() => setFilter('all')}>
      Hapus filter
    </button>
  </div>
)}
```

## Rekomendasi

**Solusi 1** adalah yang paling tepat karena:
- Memisahkan concern: notifikasi vs kontrol filter
- User selalu punya cara untuk keluar dari filter
- Tidak ada state yang "terjebak"
- Mudah dipahami dan di-maintain

**Solusi 2** cocok jika Anda ingin UX yang lebih "otomatis" — filter hilang sendiri ketika tidak relevan lagi.

**Solusi 3** terbaik jika Anda ingin filter survive refresh dan bisa di-share via URL.
